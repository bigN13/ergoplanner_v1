1. SPRINT INITIALIZATION
   a. Sprint number and dates
   b. Sprint goal definition
   c. Team capacity calculation
   d. Review previous sprint metrics

2. BACKLOG GROOMING
   a. Review product backlog
   b. Update story points
   c. Clarify requirements
   d. Identify blocked items
   e. Remove obsolete items

3. SPRINT BACKLOG CREATION
   a. Select stories based on:
      - Priority (P0, P1, P2)
      - Dependencies resolved
      - Team capacity
      - Sprint goal alignment
   b. Total story points should be 80% of capacity

4. TASK BREAKDOWN
   For each selected story:
   a. Create implementation tasks
   b. Create testing tasks
   c. Create documentation tasks
   d. Assign effort hours
   e. Identify dependencies

5. RISK IDENTIFICATION
   a. Technical risks
   b. Dependency risks
   c. Resource risks
   d. External risks
   e. Create mitigation plans

6. SPRINT SCHEDULE
   Create day-by-day plan:
   a. Day 1-2: Planning and setup
   b. Day 3-8: Implementation
   c. Day 9: Testing and bug fixes
   d. Day 10: Demo and retrospective

7. SUCCESS CRITERIA
   Define measurable goals:
   a. Stories completed
   b. Bug count < threshold
   c. Code coverage > 80%
   d. Performance metrics met
   e. Documentation updated

8. OUTPUT GENERATION
   Create sprint-[number]-plan.md with:
   a. Sprint goal
   b. Selected stories
   c. Task assignments
   d. Risk register
   e. Daily schedule
   f. Success metrics
